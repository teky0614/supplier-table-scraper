# 03 · 抓 N 款字段

范围：**只处理「标红且在共享表无记录」的 N 款**，不动未标红商品。

## 节奏（防风控）

- 每个链接**从头到尾只打开一次**：下架检查 → 截图识 SKU → 取广告图 URL → 下载图片抓 JAN，全部在这次打开内完成，然后关。
- 不允许为了看 JAN 反复打开同一商品页。JAN 从下载的图片上读，不回到页面读。
- 每次打开之间随机停顿，滚动位置/速度/停顿时长都随机，别用固定值。
- 遇淘宝验证框 → 立即停，通知用户。

## 第一步永远是下架检查

页面出现「商品已经下架啦」/「已售罄」/ 找不到购买按钮 → 判定下架：

1. 不抓字段、不写 `fields.json`。
2. 记入「下架剔除清单」。
3. 回删总表该整行（先备份、精确核对标题、删后复核行数与相邻行）。
4. 当场告知用户（门禁 C）。

**即使还能看到旧 SKU 和详情图，也不得录入**——抓得到不代表能卖。这条是 2026-11-20「潦草小狗公仔」踩出来的。

## SKU 识别（截图，不读 DOM）

截图后放大，肉眼读两块：

| 目标 | 位置 | 写入 |
|---|---|---|
| 颜色分类 | 第一个 SKU 的「原袋××个」→ **只取数字** | G 列 `color`（纯数字，如 `20`） |
| 蛋壳直径 | SKU 里的「蛋壳直径 ΦNNmm」→ **只取数字** | H 列 `dia`（纯数字，如 `65`） |

- **袋规/直径一律只存纯数字**（2026-11-26 用户规则）：`原袋20个` → `20`、`Φ65mm` → `65`。脚本层 `common.norm_color()` 会兜底提取第一段数字，但 AI 抓字段时就应写纯数字，保证总表 G 列与共享表 C 列一致。
- 禁止读页面文字元素、禁止 `evaluate` 抓 innerText。截图用完立即删。
- 缩略图会看错数字，必须放大原图逐位看。

## 广告图（要的是印 JAN 的那张）

判定特征：

- 本店竖版详情图（UID `2208320477407`），**高度 > 宽度**
- 图上有印刷的 JAN 条码，是包装图，**不是主图**
- BANDAI 管理番号（如 `751293-2838810-300`，带连字符）**不是 JAN**，不填

懒加载图常见 `naturalWidth = 1` 是占位，**直接下载 URL 看真实尺寸**再判断，别在页面上等。

只取图片 URL，不读图片周围的文字。

## JAN 四重验证（数字绝不能错）

```bash
"$PY" "$S/jan_verify.py" img=<图片> out=<目录> crop=<x,y,w,h> zoom=8
```

1. 下载原图 → 裁剪条码区 → 放大 5~10 倍（最多 12 倍）
2. zxingcpp 机器解码
3. GS1 校验：前 12 位「奇位×1、偶位×3」求和，校验位 =(10−和%10)%10，须等于第 13 位
4. 放大图**肉眼逐位复核**（首位常单独印在条码左侧）

### 冲突处理（血泪案例）

| 情况 | 处理 |
|---|---|
| zxing 与放大原图不一致 | **以放大原图为准**。曾出现 zxing 解出 `1817180191102` 且 GS1 恰好通过（1/10 概率巧合），放大图清晰是 `4904790088759`；原因是 zxing 只扫到条码顶部残缺横线（识别框仅 9px 高）。GS1 通过**不能**单独作为采用依据。 |
| GS1 不通过 | 先换更高倍数重裁、换不同区域交叉核对。① 曾把「08」读成「10」，超放大后修正为 `4904790086908` 才通过；② 另一款放大逐位清晰但校验位就是不符（图上印错）→ 按原图写入并在汇报中标注请用户复核，**不要硬凑一个能通过的值**。 |
| 多个候选 | 多张裁剪交叉确认，仍不定就报给用户，不挑一个 GS1 通过的凑数。 |

## 尺寸的三种特殊情形（2026-11-21 用户拍板）

| 情形 | 处理 |
|---|---|
| SKU「蛋壳直径」栏写的不是直径（如「高：4厘米」） | **H 留空**，不换算。JSON 里 `dia:""`；payload 脚本会自动跳过 E 列 |
| SKU 显示两个直径（如「Φ50mm、Φ65mm」） | H 填 `50/65`（两值都写，文本） |
| SKU 值与广告图印刷值不一致（SKU Φ75、图上 74mm） | **以 SKU 为准**，汇报中标注差异 |

## 字段 JSON

```json
[{"row":2,"title":"<清洗后标题>","color":"6","dia":"50",
  "jan":"4904790906244","img":"https://...jpg","cost":490}]
```

- `row` = 测试副本行号，即 `mark` 之后的第 2~(N+1) 行。
- `title` 必须与该行 B 列完全一致（`fill` 会校验，不符直接报错）。
- `cost` 取总表成本列，留给袋价换算。
- **下架款不写进来**——后续所有阶段只处理 JSON 里有的款。

## 收尾自检

- [ ] N 条 = 标红条数 - 下架剔除条数
- [ ] 每条 `color` 是纯数字（如 `20`，非「原袋20个」）、非空；`img` 是 URL；`jan` 13 位纯数字
- [ ] `dia` 是纯数字（如 `65`），允许为空但空值必须在汇报里点名是哪款、为什么
- [ ] 标注了所有「JAN 存疑/尺寸特殊」的款，等用户确认
