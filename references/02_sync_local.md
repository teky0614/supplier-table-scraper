# 02 · 同步本地总表

## 输入输出

| | 路径 |
|---|---|
| 临时表（采集产物） | 表头 `序号 / 商品标题 / 商品链接 / 价格（元）` |
| 总表（真表，只读） | 表头含 `标题未清洗 / 清洗后标题 / 链接 / 原袋价格 / 颜色分类 / 蛋壳直径 / 广告图 / 编码` |
| 输出 | `diff.json`（清单）+ `总表_测试.xlsx`（落地副本）+ `总表_基准.xlsx`（同步后快照） |

列全部按表头名定位。别名表在 `table_ops.py` 的 `ALIASES`；同一个 key 命中多个不同列会**直接报错**（例如表里同时有「原袋价格」和「价格」），这时要问用户，不许猜。

## 三条同步规则

1. **正向（新增）**：临时表有、总表没有 → 插到表头下（第 2 行起），保持临时表内原始顺序。
2. **反向（删除）**：总表有、临时表没有 → 删整行。删除是自下而上按行号删，不按"相同行号"对应（两表顺序本来就不同）。
3. **剔除**：`价格 > 700` **或** 原始标题不含「扭蛋」→ 两边都不要。
   - ⚠️「不含扭蛋」必须用**原始标题**判断（总表`标题未清洗` / 临时表`商品标题`）。用清洗后标题判断会误删几乎所有行——那一列本来就把「扭蛋」删掉了。

## 标题清洗（只作用于新插入行）

```
1. 去掉开头「日本正版」（连同其后空格）
2. 找【最后一个】「扭蛋」，删掉它和它后面所有文字，去尾部空格
例：日本正版TOMY 三丽鸥白菜装扮造型扭蛋 凯蒂猫美乐蒂玉桂狗 -> TOMY 三丽鸥白菜装扮造型
```

- 不含「扭蛋」的（盒蛋/景品/手办）只做第 1 步。
- 「台湾正版」等前缀**保留原样**，规则只要求去「日本正版」。要额外处理先问用户。
- 清洗只在插入时算一次；老行不动。

## 护栏（这条最容易救命）

```
覆盖率 = 临时表有效标题数 / 总表商品行数
覆盖率 < min_ratio(默认0.9)  -> guard.ok=false
删除条数 > 总表行数 30%       -> guard.ok=false
```

`guard.ok=false` 时 `sync_apply` 直接拒绝。原因只有一个：**采集视图不是全店**（点了某个分类、或排序后只抓了第一页）。这时候做反向删除＝把总表整片删掉。

强行放行只能 `force=1`，且必须先向用户确认「本次采集范围到底是什么」。

## 保护行（永不参与匹配、永不删除）

- 空标题行
- 以 `联系 / 备注 / 说明 / 合计 / 总计` 开头的行
- 含 `VX` 的行（如 `联系VX：xxx`）

## 重名与链接不一致

- 临时表或总表内出现**同名标题多行** → 记为 `dup_title_*` 告警。是否去重**问用户**，脚本不擅自处理（历史上出现过同标题不同价的真商品）。
- 同名但**链接不同** → 记为 `link_mismatch`。可能是两家店同款，也可能是改名，**按铁律一律不推断**，报给用户。

## 落地后自检

`sync_apply` 自己会跑一次多重集校验：

```
期望 = 新插入标题 + (原总表标题 - 已删行)
实际 = 写入后副本的非保护行标题
不相等 -> 直接抛错，不产物
```

随后标色：新插入行为浅粉 `FFFFC7CE`，其余数据行一律清标（源表常自带历史标红），表头不动。

## 坑

| 现象 | 原因 |
|---|---|
| 报「删行前核对失败」 | 行号漂移或标题被改过；说明 diff.json 与当前文件不同源，重跑 sync_plan |
| 报「表头歧义」 | 表里有两列近似名；先 `headers` 看清单，问用户确认 |
| 插入后公式列变空 | 正常：新行只填 标题/链接/成本/清洗后标题，其余留白 |
| 老行底色被清掉 | 这是设计：每次同步只保留「本次新增」的粉标，避免历史标记堆积 |
| 覆盖率 0.5 但确实是全店 | 总表里有大量已下架历史；确认后 `force=1`，或先让用户临时把历史行移走 |
